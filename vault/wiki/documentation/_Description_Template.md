# Description.md Template

> This template defines the structure for all mod description files.
> Each Description.md lives alongside its parent mod file inside its numbered folder.

## Structure

### 1. Opening Hook (1-2 sentences)
A compelling, action-oriented first impression. What does this mod bring to Minecraft?
Should make the reader immediately want to know more.

### 2. The Name (pronunciation + meaning + relation)
Must include:
- **Latin name** and its English pronunciation (phonetic)
- **Literal meaning** in plain English
- **How the meaning connects** to what the mod actually does in-game

Format example:
> **"Materia"** (pronounced *eh-leh-MEN-tum*) — Latin for "element, fundamental substance."
> The name tells you exactly what this mod is: the building blocks everything else is made from.

### 3. What's Inside (feature list)
Key items, blocks, or systems the mod adds. Written for a Minecraft player, not a developer.
Focus on gameplay impact, not internal architecture.

### 4. How It Fits (ecosystem context)
Which pack(s) does it belong to (Ars Vitae / Ars Mundi)?
Does it depend on other mods? What complements it?

### 5. Why You Want It (closing hook)
One compelling sentence or short paragraph. What experience does this mod unlock?

## Rules
- **Minimum 200 characters** per file (but aim for 400-800 for richer content)
- Written for Minecraft players browsing a mod website — not developers
- No technical jargon (no "DeferredRegister", "JSON data-driven", etc.)
- Keep the Latin flair — it's the ecosystem's identity
- Each description should make a player excited to install
- This is iteration 1 — will be enriched later
